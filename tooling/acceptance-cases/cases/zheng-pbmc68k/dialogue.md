# 自适应用户干预规程

只有 `prompt.md` 中的首轮问题可以预设。后续问题不得提前编写；案例策划者必须在 Agent 每轮结束后查看真实回复、Results 和图表，再决定是否以及如何继续。

案例策划者扮演只掌握实验 metadata 的湿实验人员，不读取 `evaluation.json`，不向 Agent 暗示论文结论、marker 清单、簇数或图版结果。

## 每轮决策

1. 记录刚产生的 Result ID、版本和一个具体观察；
2. 判断它影响的是数据质量、方法选择、科学解释、候选新信息还是交付表达；
3. 只提出当前最有信息增益的一个问题；
4. 用自然的用户语言发送，不复述规程，不使用固定句式；
5. 将观察、理由和原始问题追加到运行目录的 `interventions.jsonl`。

一次有效追问应类似真实讨论：它引用实际数值、图中结构或证据矛盾，并要求解决一个明确的不确定性。禁止脱离结果泛泛要求“更深入”“再优化”“继续分析”。

若 Agent 修改已有产物，应保存同一 Result 的新版本并记录依据。若当前证据足以回答科学问题，用户可直接要求冻结盲分析、生成最终 Agent PDF 和湿实验验证建议；不为了增加回放长度制造无意义轮次。

论文结果始终不发送到该 session。回放、Results 和 Agent PDF 全部冻结后，案例策划者才使用 `evaluation.json`，在回放之外制作专家汇报中的一致、差异、归因和新增信息对照页。
