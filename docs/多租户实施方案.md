# 多租户实施方案

> 面向内网多用户 Web 场景的容器化多租户方案。
> 操作步骤见 [`多租户运维手册.md`](./多租户运维手册.md)。
>
> 环境：192 核 / 1.5 TiB / 4×RTX 5090 / Rocky Linux 9.3 / podman 4.6.1 rootless。

---

# 一、结论

**一名用户一个容器。容器是隔离边界；身份只在网关；模型密钥不出网关；环境分三层。**

## 三个不变量

| 不变量           | 含义                                                                               | 代价                 |
| ---------------- | ---------------------------------------------------------------------------------- | -------------------- |
| **身份在网关**   | 服务端无调用者身份概念（唯一凭据是全局共享 bearer）。用户↦租户的映射只能由网关强制 | 网关是唯一入口       |
| **密钥不出网关** | 租户容器只持有占位符；真密钥在网关注入                                             | 网关持有全部密钥     |
| **环境分层**     | 共享工具链只读挂载；长尾依赖落在项目自己的可写层                                   | 租户磁盘各自一份长尾 |

## 关键约束

| 约束         | 事实                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| URL 形态     | `https://<IP>/prj_.../session/...`，**无端口**。所有用户同一个 URL，租户由认证身份决定                               |
| 租户粒度     | 一人一容器。同租户多用户会共享凭据、策略、信任、偏好、作业列表（服务端无用户身份）                                   |
| 域名         | SPA 用绝对资源路径，**路径前缀路由会全部 404**；`AXIOMICS_CORS_DOMAINS` 只信任 `https://<子域>.<apex>`，裸 apex 拒绝 |
| 服务端命令   | 必须 `serve`，**不能用 `web`**（`web` 会探测 4096/4097 并静默接管已运行的服务器）                                    |
| 共享环境路径 | conda shebang 是绝对路径，**必须挂到同一路径**                                                                       |
| 容量         | 每租户约 320 MB；1.5 TiB 下余量充足                                                                                  |

# 二、架构

```
浏览器
  │  https://<IP>/prj_.../session/...        ← 所有用户同一 URL，无端口
  ▼
Caddy :443
  ├─ /auth*  ──→ Authelia（登录门户，收进路径下）
  ├─ forward_auth ──→ Authelia :9091（内部端口）
  ├─ 身份 → 租户 ID → 上游端口 + 该租户 token
  └─ SPA 绝对资源与 API 同样按身份路由回同一容器
        │
        ▼
  127.0.0.1:<port>（端口发布，用户不可见）
        │
        ▼
  容器 ax-<租户ID>
  ├─ relay :8080 ──→ 127.0.0.1:4096（axiomics 只绑 loopback）
  ├─ axiomics serve :4096
  ├─ 四卷：data / config / cache / state
  ├─ 共享工具链（只读挂载，同一路径）
  └─ 项目 .venv（可写，长尾依赖落这里）

模型调用：
  容器 ──Bearer <占位符>──→ Caddy :43001 ──Bearer <真密钥>──→ api.deepseek.com
```

# 三、五条支撑判断

## 判断 1｜隔离：容器已满足「不知道也不影响」，权限保持最严

| 维度       | 状态                                |
| ---------- | ----------------------------------- |
| 进程       | PID namespace，租户内 `ps` 只见自己 |
| 网络       | 独立 netns，租户间端口不可达        |
| 文件       | 独立四卷，互不可读                  |
| 内核       | **共享**（已接受的唯一缺口）        |
| 服务端鉴权 | 每租户独立 token，无 token `401`    |

容器权限保持最严：不需要放宽 seccomp，不需要加 capability。

**信息面已封闭的五个泄露点**（不加掩码时租户可见宿主全貌）：

| 泄露点                      | 暴露内容                                                 | 处置                                 |
| --------------------------- | -------------------------------------------------------- | ------------------------------------ |
| `/proc/driver/nvidia/gpus/` | 宿主全部 GPU（总线地址 + UUID）                          | 容器掩码                             |
| `/sys/bus/pci/devices/`     | 460 个 PCI 设备                                          | 容器掩码                             |
| `/sys/devices/`             | 整个硬件树                                               | 容器掩码                             |
| `/sys/class/drm/`           | DRM 设备                                                 | 容器掩码                             |
| `dmesg`                     | 宿主内核日志（4409 行），含全机 GPU 初始化与其他容器事件 | **宿主级 `kernel.dmesg_restrict=1`** |

## 判断 2｜算力：GPU 按容器分区

按容器切卡（`--device /dev/nvidia<N>`）后：

- 容器只看见被分配的那张卡（`DEVICE_COUNT: 1`）
- 全仓无 `CUDA_VISIBLE_DEVICES` 分配代码；bwrap 绑定「看得见的」设备，而容器只看得见被给的那张
- **「两个作业都抢 cuda:0」在隔离层解决，零代码**

| 项         | 值                             |
| ---------- | ------------------------------ |
| 宿主 GPU   | 4× RTX 5090（32 GB/张）        |
| 每租户     | 1 张，静态绑定                 |
| 加固后功能 | `CUDA: True / device_count: 1` |

需绑定 NVIDIA 用户态库（`libcuda` / `libnvidia-ml` / `ptxjitcompiler` / `allocator` / `cfg` / `nvvm`）。
**手工绑定在驱动升级后会失效**，生产应改用 `nvidia-container-toolkit` 生成 CDI。

## 判断 3｜生命周期：回收是秒级且安全的

| 指标                    | 值                                        |
| ----------------------- | ----------------------------------------- |
| `podman stop -t 10`     | 0.09 秒，退出码 143（SIGTERM → 优雅关闭） |
| `podman start` → 可服务 | 0.77 秒                                   |
| 状态保留                | 项目数、会话数零丢失                      |

**回收判据必须两条同时满足**：

1. 无 HTTP 活动持续 T
2. 容器内**非僵尸**工作进程数 == 0

**两条纪律**：

- **必须排除僵尸**：容器内会累积 defunct，不排除则永远判定为「忙」
- **不能只看 HTTP 空闲**：本地作业是 detached 子进程（`stamo` 声明 12 小时），误停会杀掉长任务

## 判断 4｜标识：本地分配的不透明序号，永不复用

```
u0001                    ← 主键，不由任何 IdP 派生
 ├ 容器名   ax-u0001
 ├ 卷路径   /srv/axiomics/tenants/u0001/
 └ 属性     idp_subject / username / email / created_at / state
```

| 判据            | 理由                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------- |
| 稳定性          | 用户名可改、可回收、可能含 PII。**把外部系统的可变属性当自己的持久化键，就是破坏性变更的来源** |
| 换 IdP 不搬数据 | IdP 身份是映射表里的一列，换 IdP 改一列，容器与卷不动                                          |
| 回收安全        | 离职即封存 ID，新人拿新号 → 不继承前任数据                                                     |
| 无 PII 入库     | 路径、日志、备份名里没有姓名 / 邮箱                                                            |
| 不暴露          | URL 对所有用户相同，标识符不出现在浏览器                                                       |

**反模式**：租户 ID 用用户名 / 邮箱前缀 / 工号 / UUID，或携带任何含义。

## 判断 5｜状态：控制面用文件，数据面分散

| 控制面数据         | 位置                                       | 形态                         |
| ------------------ | ------------------------------------------ | ---------------------------- |
| IdP 身份 → 租户 ID | `tenants.map`                              | 纯文本，Caddy `import`       |
| 租户 token         | 一租户一文件（0600），Caddy `{file.}` 读取 | 文本                         |
| 认证会话           | Authelia SQLite                            | 身份系统内部状态，不并入业务 |
| 审计               | Caddy access log                           | 文本                         |
| 用量               | 模型网关请求日志                           | JSONL                        |
| 存活               | `podman ps` 查询                           | 无持久化                     |

**数据面（会话、项目、结果）留在各租户数据根，不集中**：

| 理由         | 说明                                                                                  |
| ------------ | ------------------------------------------------------------------------------------- |
| 违反零改动   | axiomics 的 Storage 是**进程内文件 JSON + 本地文件锁（O_EXCL）**，无远程/共享存储设计 |
| 破坏容器边界 | 中心库一旦失守，全部租户数据在其中                                                    |
| 锁不跨容器   | O_EXCL 文件锁在多容器共写一个库时失效                                                 |

**axiomics 不使用 SQLite**；租户数据根下零个 `.db` / `.sqlite` 文件。

# 四、部署形态

## 4.1 三层环境

| 层         | 容器内位置         | 权限     | 谁写              |
| ---------- | ------------------ | -------- | ----------------- |
| 共享工具链 | `<共享环境根>`     | **只读** | 仅平台安装流程    |
| 项目长尾   | `<项目目录>/.venv` | 可写     | agent 自动 pip 装 |
| 会话缓存   | 会话工作区         | 可写     | agent             |

共享环境**永不复制**（51 GB × N 不可接受），挂同一路径。长尾依赖落项目 `.venv`，不影响共享环境。

## 4.2 容器标志集

**十项，每项都有非加不可的理由。**

| 标志                        | 作用                 | 不加的后果                                                     |
| --------------------------- | -------------------- | -------------------------------------------------------------- |
| `--init`                    | 回收僵尸             | 每 HTTP 请求泄漏一个僵尸 → PID 表耗尽 → 无法 fork              |
| `--userns=keep-id`          | bwrap 建嵌套命名空间 | `Creating new namespace failed`                                |
| `--security-opt unmask=ALL` | bwrap 挂 procfs      | `Can't mount proc on /newroot/proc`                            |
| `mask=/proc/driver/nvidia`  | 隐藏宿主 GPU 清单    | 租户可见宿主全部 GPU                                           |
| `mask=/sys/bus/pci`         | 隐藏 PCI 枚举        | 租户可见 460 个设备                                            |
| `mask=/sys/devices`         | 隐藏硬件树           | 租户可见整机硬件                                               |
| `mask=/sys/class/drm`       | 隐藏 DRM             | 租户可见 11 个 DRM 设备                                        |
| `-e HOME=<可写>`            | 可写 homedir         | 沙箱内 `HOME=/` → `mkdir /.axiomics` EACCES → 命令输出变崩溃栈 |
| 清空 `*_proxy`              | 断继承               | 继承 SSH 隧道代理 → 模型调用连接被拒                           |
| `NODE_EXTRA_CA_CERTS`       | Bun 信任内部 CA      | **Bun 不读系统 CA bundle** → TLS 校验失败                      |

宿主级另需：`net.ipv4.ip_unprivileged_port_start=443`、`kernel.dmesg_restrict=1`（须持久化到 `/etc/sysctl.d/`）。

## 4.3 入口脚本的两个职责

```sh
socat TCP-LISTEN:8080,fork,reuseaddr TCP:127.0.0.1:4096 &
exec /usr/local/bin/axiomics "$@"
```

**① relay 必需，且必须用 `socat`**：axiomics 只绑 `127.0.0.1`（无 hostname 选项），端口发布打的是容器 eth0 → 连接被 reset。这是容器与 microVM 的共同成本。
不能用 `ncat -l --keep-open --sh-exec`：它每个连接泄漏一个不退出、且仍持有继承来的监听 socket 的子进程，实测攒到 100 个后 listener 停止 accept，**租户整个失联**（后端 4096 始终健康，只有中继死了）。

**② 项目 Python 层不在容器里**：bash 工具在 spawn 前会等 `pythonRuntime("python")`。该函数优先用 `<项目目录>/.venv`；没有时它会构建 conda 起始环境，而**容器访问不了 `conda.anaconda.org`** → **永久阻塞**，工具状态永远停在 `running` 而容器内无任何进程。补齐改在宿主侧由 reclaim timer 触发——放进容器的 `sleep` 循环会被算作"有工作在跑"，污染回收判据。

## 4.4 网关

| 要点                  | 说明                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| 独占 443              | 登录门户收进 `/auth` 路径，用户看不到任何端口                                                        |
| 必须 `route { }`      | Caddy 指令顺序中 `handle` 在 `forward_auth` 之前，直接用它**会绕过认证**                             |
| `respond` 单 matcher  | `respond @a @b 403` 会把 `@b` 当响应体且条件失效                                                     |
| 模型网关站点不带 host | 写成 `https://<IP>:43001` 只匹配该 Host；租户用 `host.containers.internal` 访问 → **静默返回空 200** |
| 改配置后核对站点数    | 少写一个站点 = 静默不监听，直到有人调用才暴露                                                        |
| 证书 SAN              | 必须覆盖租户访问网关用的名字（含 `host.containers.internal`）                                        |

## 4.5 权限与模型

- **权限完全放开**：租户配置 `sandbox.enabled=false` → 项目默认 `mode=full`，无权限弹窗。
  耦合说明：`mode=full` 同时关闭项目内的二级沙箱（容器已是完整边界，可接受）。
- **租户零密钥**：租户 `axiomics.json` 里 `apiKey` 是占位符，`baseURL` 指向模型网关；
  网关注入真密钥。换模型来源对租户完全透明。
- **模型目录可用配置增改**（`provider.<id>.models`），默认模型由 `model` 键指定，**无需重建二进制**。

# 五、未来接入中心统一身份

**破坏性变更的唯一来源是租户标识键，不是认证组件。**

| 层                          | 用什么                           | 换中心 IdP 时                      |
| --------------------------- | -------------------------------- | ---------------------------------- |
| 数据面键（容器名 / 卷路径） | 本地分配的稳定序号               | **永不变**                         |
| 身份映射                    | `tenants.map`                    | 换键值，容器不动                   |
| 认证链路                    | 标准 OIDC → oauth2-proxy → Caddy | **只改 oauth2-proxy 的 OIDC 配置** |

用 oauth2-proxy 而非 Authelia 原生 forward-auth 的理由：换 IdP 时前者只改两行 OIDC 配置，
后者要改 Caddy 认证块 + 头名 + 映射键。Authelia 本身也是 OIDC Provider，今天是
`Authelia(OIDC) → oauth2-proxy → Caddy`，将来换 issuer 即可。

**两条纪律**：开通脚本以「租户 ID」为唯一键；容器名与卷路径永不含用户名。

# 六、已知边界

| 项                      | 状态                                                                           |
| ----------------------- | ------------------------------------------------------------------------------ |
| 共享内核                | 已接受。容器提供 PID / Mount / User / Net namespace + cgroup，缺的只有内核隔离 |
| cgroups v1              | `--cpus` / `--memory` 被静默忽略。需硬配额须启用 cgroups v2（重启级变更）      |
| 网关持有全部租户 token  | 一租户一文件（0600），不进配置文件、不进 git                                   |
| NVIDIA 用户态库手工绑定 | 驱动升级会失效，应换 CDI                                                       |
| 容器出口白名单          | 可达 PyPI 等；**不可达 `conda.anaconda.org`**（这是 `.venv` 方案的前提）       |
| 同租户多用户            | 共享凭据、策略、信任、偏好、作业列表；只有 sessionID 级隔离                    |
| 未验证                  | 端到端跑通一个真实 GPU 能力（`scvi` / `stamapper`）                            |
